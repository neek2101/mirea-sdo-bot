# Бот СДО РТУ МИРЭА

Telegram-бот для [online-edu.mirea.ru](https://online-edu.mirea.ru) (Moodle). Входит в СДО от имени студента и сообщает о важном — чтобы не пропустить контрольную.

## Что умеет

- **Сразу после входа** присылает сводку: какие тесты и задания **уже идут**, какие **скоро откроются**, что просрочено, но ещё принимается.
- **Новые тесты и задания** — как только появились в СДО.
- **Открытие теста** — в момент, когда он становится доступен.
- **Перенос срока** — «было / стало / продлили на N».
- **Напоминания** перед сроком (по умолчанию за сутки и за 3 часа; настраивается: 72/24/12/6/3/1 ч). После простоя приходит одно, ближайшее, а не пачка.
- **Новые материалы** в курсах (файлы, страницы, ссылки…) и **новые курсы**.
- **Новые оценки** — по конкретным работам, с итогом курса.
- **Уведомления самой СДО** (колокольчик Moodle).
- По кнопке **📊 Оценки** — текущие баллы по каждой дисциплине, а по нажатию на дисциплину — оценки за каждую работу.

Меню: 📅 Сроки · 📊 Оценки · 🔄 Обновить · ⚙️ Настройки. Команды: `/login`, `/logout`, `/help`, `/cookie`.

## Как устроено и почему так

Перед написанием изучены существующие решения и сам Moodle:

| Вопрос | Что выяснилось | Решение |
|---|---|---|
| Официальный API Moodle | Мобильный веб-сервис (`login/token.php`) в СДО МИРЭА выключен — это отмечают и другие проекты для online-edu.mirea.ru | Работаем как сама веб-страница: cookie сессии → `sesskey` → `lib/ajax/service.php` |
| Вход | Единый вход МИРЭА (Keycloak) с кодом из почты и шагом «МАКС» | Не пишем свой: диалог с Keycloak уже реализован в библиотеке [pymirea](https://github.com/silverhans/pymirea). Дальше — обычный OpenID Connect: `/auth/oidc/` СДО с живой SSO-сессией выдаёт cookie Moodle без формы |
| Какие AJAX-функции доступны | Сверено по исходникам Moodle 4.1 и 4.5 (`db/services.php`): календарь, курсы, содержимое курса, уведомления — с `'ajax' => true` | Отчёты об оценках через AJAX недоступны → читаем HTML-страницы отчётов, разметка сверена с исходниками Moodle |
| Telegram | Стандарт сообщества — [aiogram 3](https://github.com/aiogram/aiogram) | aiogram 3.31, FSM для входа |

Готовые проекты для СДО МИРЭА ([mirea-works](https://github.com/keepmeinyourmind/mirea-works), [mirea-deadlines-bot](https://github.com/LightSix56/mirea-deadlines-bot)) просят вручную копировать cookie из DevTools или ссылку экспорта календаря и не показывают баллы. Их находки (AJAX-путь, закрытый мобильный сервис) использованы, а вход сделан через логин и пароль с кодом из почты. Ручной ввод cookie оставлен запасным вариантом: `/cookie`.

**Зависимости — без зоопарка:** aiogram, pymirea (тянет httpx, beautifulsoup4, cryptography), aiosqlite, pydantic-settings. Планировщик — обычные задачи asyncio, хранилище — один файл SQLite.

### Надёжность

- **Опрос в три шага:** скачать всё из СДО → сравнить с прошлым снимком в памяти → **одной транзакцией** записать новый снимок вместе с сообщениями в очередь. Обрыв сессии посреди опроса, падение процесса или недоступный Telegram не «съедают» уведомления.
- **Очередь исходящих:** сообщение удаляется только после того, как Telegram его принял. Напоминания с прошедшим сроком не доставляются с опозданием.
- **Ошибка ≠ «всё удалили».** Каждый источник (задания, материалы, оценки, уведомления) сравнивается только если получен целиком.
- **Сессия СДО истекла** → бот молча перевходит через сохранённую SSO-сессию. Не вышло → один раз просит войти заново.
- Если Telegram недоступен при старте — бот ждёт связь с нарастающей паузой, а не падает.

### Безопасность

- **Пароль не сохраняется**: он нужен один раз для входа, сообщение с ним бот сразу удаляет из чата.
- В базе хранятся только cookie СДО и SSO-сессии, **зашифрованные** (`SessionCrypto` из pymirea: Fernet + HKDF, с ротацией ключей).
- `/logout` удаляет все данные пользователя.

## Запуск

1. Создай бота у [@BotFather](https://t.me/BotFather) и получи токен.
2. Подготовь настройки:
   ```bash
   cp .env.example .env
   python -c "import secrets; print(secrets.token_urlsafe(32))"   # → SECRET_KEY
   ```
   Заполни `BOT_TOKEN` и `SECRET_KEY` (остальное — по желанию, см. комментарии в `.env.example`).
3. Запусти:
   ```bash
   docker compose up -d --build
   docker compose logs -f
   ```

Без Docker (Python 3.11+):
```bash
python -m venv .venv && . .venv/bin/activate
pip install .
python -m sdo_bot
```

> Если сервер в российском дата-центре и Telegram с него недоступен, задай `TELEGRAM_PROXY` и поставь `pip install ".[proxy]"`. Если МИРЭА не пускает IP сервера — `MIREA_PROXY`.
>
> Дома с VPN (Happ, v2rayN и т. п. в режиме системного прокси): бот игнорирует системный прокси, поэтому МИРЭА открывается напрямую. Telegram направь через локальный порт VPN-клиента: `TELEGRAM_PROXY=http://127.0.0.1:10808`. VPN при этом должен быть включён, но не в режиме TUN.

## Настройки (`.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BOT_TOKEN` | — | Токен от @BotFather |
| `SECRET_KEY` | — | Ключ шифрования сессий. **Не терять**: без него все войдут заново. Ротация: `новый,старый` |
| `POLL_INTERVAL_MINUTES` | 15 | Период опроса СДО (≥5) |
| `POLL_CONCURRENCY` | 3 | Сколько пользователей опрашивать параллельно |
| `EVENTS_LOOKBACK_DAYS` | 30 | Глубина календаря назад (видеть уже открытые тесты) |
| `MOODLE_URL` | https://online-edu.mirea.ru | Адрес СДО |
| `MIREA_PROXY`, `TELEGRAM_PROXY` | — | Прокси (см. выше) |
| `DATABASE_PATH` | data/bot.sqlite3 | Файл базы |

## Что проверить при первом запуске

Код проверен на поддельном сервере, который повторяет форматы Moodle 4.x и редиректы единого входа, но **сам online-edu.mirea.ru из среды разработки был недоступен**. Поэтому при первом запуске стоит убедиться в двух вещах:

1. **Вход через `/login`.** Если после кода из почты бот пишет «Вход в МИРЭА прошёл, но СДО не открылась», значит, у СДО другой адрес входа через МИРЭА, чем `/auth/oidc/`. Пока это не исправлено, работает запасной `/cookie` (инструкция — в ответе на команду).
2. **📊 Оценки.** Если список пуст, хотя в СДО оценки есть, — у темы оформления МИРЭА нестандартная разметка отчёта. Тогда нужно поправить селекторы в `src/sdo_bot/moodle/parsers.py` (пришли HTML страницы `/grade/report/overview/index.php` — подскажу).

Журнал (`docker compose logs`) не содержит паролей, cookie и `sesskey`.

## Разработка

```bash
pip install -e ".[dev]"
pytest          # парсеры, клиент Moodle, SSO, синхронизация, напоминания, бот целиком
ruff check src tests
```

Тесты используют поддельные СДО и SSO (`tests/fakes.py`) поверх `httpx.MockTransport` и проходят весь путь от апдейта Telegram до сообщения в чат.

```
src/sdo_bot/
├── __main__.py      запуск, сборка зависимостей
├── config.py        настройки из окружения
├── moodle/
│   ├── client.py    сессия, sesskey, AJAX (с учётом того, что Moodle обрывает пачку на ошибке)
│   ├── api.py       что и каким вызовом берём из СДО
│   ├── parsers.py   разбор HTML отчётов об оценках
│   └── sso.py       вход через единый вход МИРЭА (pymirea) и тихий перевход
├── sync.py          снимок → сравнение → события; напоминания
├── storage.py       SQLite: пользователи, снимок, очередь сообщений
├── scheduler.py     фоновый опрос, напоминания, доставка из очереди
├── render.py        тексты сообщений
└── bot/             обработчики aiogram: вход, меню, настройки
```

## Ограничения

- Moodle показывает в календаре только задания, **требующие действия**: сданное оттуда пропадает (бот считает его выполненным и больше не напоминает).
- Оценки берутся из отчётов СДО. Баллы БРС из «Пульса» — другая система, сюда не входят (технически их умеет pymirea, можно добавить).
- Состояние входа (между паролем и кодом из почты) живёт в памяти: перезапуск бота в эти минуты потребует начать вход заново.
